## Resource notes

### DSA and interview practice

**AlgoMaster 150 — intended DSA spine.** URL: [DSA patterns, AM-150 tab](https://algomaster.io/practice/dsa-patterns?tab=am-150). The exact URL could not be opened by the browsing service because of its safe-URL restriction, so its problem list, pricing, solution visibility, and progress features were **not independently verified**. The public [AlgoMaster course catalog](https://algomaster.io/courses) does verify the platform’s interview scope: its DSA course promises fundamentals and 50+ coding patterns, alongside system design, LLD, concurrency, microservices, SQL, behavioural, and job-search courses.

- **Mode / depth:** intended curated pattern practice; work problem-first and use explanations only after a serious attempt. The catalog does not independently establish the AM-150’s exact pattern count, difficulty mix, or time estimate. Treat the common “150” label as an item count, not a verified syllabus or duration.
- **Assumptions:** one interview language and its standard library; basic loops, functions, arrays/maps, Big-O, and debugging. Learn those before starting, rather than spending early problems fighting syntax.
- **Recommendation:** **primary** DSA practice spine if the user can open it. Complete it once with spaced review; do not substitute company-tagged grinding for the first pass. Direct companion: [AlgoMaster DSA course listing](https://algomaster.io/courses).
- **Overlap:** DSA Handbook covers the same foundations and patterns more encyclopedically; PracHub supplies employer reports rather than a learning sequence. Use them as reference/calibration, not competing backlogs.

**AlgoMaster courses.** URL: [courses](https://algomaster.io/courses). **Access:** the catalog is public; it labels 9 interview-preparation courses, 2 AI/ML courses, 5 language courses, and Git. The catalog itself does not establish which chapters/exercises are free versus premium. **Breadth:** unusually broad for interview preparation: DSA; system-design fundamentals/interviews; LLD; concurrency; microservices; SQL; behavioural; job search; plus AI engineering and ML system design. **Mode:** structured courses, so likely concept-first with an interview framing; only the catalog scope was verified. **Assumptions:** select a language course if needed, then foundation-level programming. **Effort:** no reliable total estimate shown in the public catalog. **Role:** primary interview umbrella if its paid/free model fits; otherwise select separate open resources below. **Direct links:** [DSA listing](https://algomaster.io/courses), [AM-150 practice](https://algomaster.io/practice/dsa-patterns?tab=am-150).

**DSA Handbook.** URL: [curriculum](https://dsa.handbook.academy/curriculum/). **Access:** target curriculum was not rendered by the browser, so chapter count, languages, and exercise availability were not re-verified here. **Mode:** open handbook/reference rather than a verified adaptive practice platform. **Prerequisites:** programming basics and asymptotic reasoning. **Effort:** no audit-supported estimate. **Role:** primary **reference** for a weak topic (e.g., graph shortest paths, DP state design, segment trees); supplementary to AM-150 as a complete read. **Overlap:** near-total conceptual overlap with the AlgoMaster DSA course; it adds value when explanation, not another list, is needed.

**PracHub.** URL: [prachub.com](https://prachub.com/). **Access:** public landing page reached; verify any solution/paywall status in the particular question before relying on it. **Breadth/depth:** company/role/interview-report orientation, spanning coding and adjacent interview topics rather than a deliberate DSA curriculum. **Mode:** searchable question bank and reported interview context. **Prerequisites:** already know the core patterns. **Effort:** no reliable public total used. **Role:** supplement in the final interview-calibration phase. **Overlap:** overlaps AM-150 coding prompts but is less pedagogically ordered.

**Deep-ML Problems.** URL: [problem index](https://www.deep-ml.com/problems). **Access:** public index reached. **Breadth/depth:** ML coding, not general interview DSA; exact count and per-problem access were not extracted from the JavaScript-light index. **Mode:** problems. **Prerequisites:** Python, NumPy/ML foundations. **Effort:** unspecified. **Role:** supplementary after ML theory; no meaningful overlap with AM-150 except coding discipline.

**TensorTonic.** URL: [assessment sign-in](https://www.tensortonic.com/auth?redirect_uri=%2Fassessments). **Access:** gated at sign-in; no assessment curriculum, counts, solution policy, or pricing was inspected. **Role:** optional assessment platform only after account access confirms relevance. ### Broad systems, ML systems, and distributed systems

**HLD Handbook.** URL: [curriculum](https://hld.handbook.academy/curriculum/). **Access:** public curriculum is reachable. **Verified breadth/depth:** explicit parts include reliability/operations and security at scale, with individual lessons typically marked intermediate/advanced and about 20–30 minutes (for example, 11 reliability chapters/5 hours and 10 security chapters/4 hours on the curriculum). This is broad across networking, data, distributed systems, architecture, SRE, security, and design cases. **Mode:** self-paced explanatory handbook with diagrams/chapters. **Prerequisites:** web/backend basics, networking, OS/database fundamentals; begin its prerequisite material if these are missing. **Effort:** only the per-part estimates exposed by the curriculum are reliable—no full-course total asserted. **Role:** primary broad HLD reference. **Overlap:** AlgoMaster’s design courses are interview-focused; Build Distributed System supplies implementation challenges. **Direct links:** [reliability part](https://hld.handbook.academy/curriculum/), [security part](https://hld.handbook.academy/curriculum/).

**Build Distributed Systems from Scratch.** URL: [course](https://builddistributedsystem.com/). **Access:** the direct fetch failed, but the publicly indexed landing page advertises 28 tracks and 343+ challenges in eight languages, each with concept explanations; actual challenge access/account requirements were not independently tested. **Breadth:** foundations through consensus, storage engines, and event-driven architecture. **Mode:** progressive, Maelstrom-compatible implementation challenges. **Prerequisites:** solid programming, CLI/testing comfort, and basic networking/concurrency; use HLD Handbook first for concepts. **Effort:** 343+ tasks is a scope count, not a duration. **Role:** supplementary/project practice—choose 1–3 tracks rather than treating it as a prerequisite to system-design interviews. **Overlap:** implementation counterpart to HLD Handbook and AlgoMaster system design.

**Cornell Virtual Workshop Parallel Programming Concepts and HPC.** URL: [roadmap](https://cvw.cac.cornell.edu/Parallel/). **Access:** public. **Verified breadth:** eight topics—parallel computation; threads/processes; HPC; memory access; program design; data communication; efficiency; large-scale thinking—plus a quiz. It explicitly teaches concepts rather than any one API. **Mode:** short self-paced conceptual roadmap. **Prerequisites:** basic serial programming/computer terminology; no coding is required to understand it, although a serial workload helps. **Effort:** no total hours published on the reached roadmap. **Role:** supplement/bridge before CUDA, distributed training, or HPC work. **Overlap:** foundational material for AI-infra and MLSysbook, but far shallower than either. **Direct link:** [program design lesson](https://cvw.cac.cornell.edu/parallel/program-design/develop-program).

**Machine Learning Systems.** URL: [mlsysbook.ai](https://mlsysbook.ai/). **Access:** public HTML, PDF, and EPUB for both volumes; companion labs/tools are linked publicly. **Verified breadth/depth:** two-volume, principles-first treatment from a single machine to fleet-scale infrastructure; the site exposes interactive labs, 20 TinyTorch modules, performance modeling (MLSys·im), hardware deployment kits, and StaffML practice. **Mode:** textbook plus build/lab/model/deploy/practice tracks. **Prerequisites:** ML fundamentals, Python, and enough systems knowledge to interpret performance trade-offs. **Effort:** no total estimate shown. **Role:** primary ML-systems reference. **Overlap:** AI-infra is more stack/project-oriented; frontier-lab track 5 is LLM-serving-specialized. **Direct links:** [Volume I](https://mlsysbook.ai/book/contents/), [Volume II](https://mlsysbook.ai/book/contents-at-scale/).

**AI Infrastructure Engineer Learning Path.** URL: [GitHub repository](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning). **Access:** public GitHub repo under MIT license. **Verified breadth/depth:** it claims a progressive 10-module path, production code stubs, 62 authored labs, and 265+ quizzes; visible modules cover cloud, containers, Kubernetes, data pipelines, MLOps, GPU/distributed training, monitoring, IaC, and LLM infrastructure. The repository itself notes that exercises are incomplete relative to an earlier promise (32 of 119), so do not assume a fully exercise-complete course. **Mode:** readings, runnable labs, quizzes, guided TODO projects. **Prerequisites:** operating system/CLI, Python, Git, Docker/cloud basics; it links a prerequisites guide. **Effort:** no audit-supported total—avoid repeating an unverified “500 hours.” **Role:** primary hands-on AI-infra route after basics. **Overlap:** MLSysbook supplies theory; this supplies production-stack practice. **Direct links:** [prerequisites](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning/blob/main/PREREQUISITES.md), [curriculum](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning/blob/main/CURRICULUM.md), [projects](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning/tree/main/projects).

## Concise DSA concept path (use AM-150 once access is confirmed)

1. **Setup (2–5 days):** pick one language; learn Big-O, arrays/strings, hash map/set, recursion basics, sorting, and library operations. Use an AlgoMaster language/DSA course or a targeted DSA Handbook section only for gaps.
2. **High-frequency linear patterns:** arrays/strings; hash tables; two pointers; fixed and variable sliding windows; prefix sums; intervals; binary search; matrix traversal. For each AM-150 problem: attempt 25–45 minutes, articulate invariant and complexity, implement, then write a one-line mistake/pattern note.
3. **Core structures:** linked lists; stack/queue; monotonic stack/deque; heap/priority queue; binary tree/BST; trie. Re-solve one previously missed problem at 1, 7, and 21 days rather than accumulating unreviewed solutions.
4. **Search and composition:** backtracking, divide-and-conquer, greedy, and graph representation. Then BFS/DFS, topological sorting, union-find, shortest paths, and MST.
5. **Dynamic programming last:** start with state/transition/base-case formulation (1-D and grid), then knapsack/subsequence/interval/tree/bitmask DP. Use the DSA Handbook precisely when a recurrence is opaque; do not read it wholesale before coding.
6. **Interview conversion (after the 150):** timed mixed sets and 1–2 mocks weekly; use PracHub only to sample target-company wording and recurring areas. Escalate to a larger sheet only if error logs show a real breadth deficit, not merely because a list remains available.

## Decision rule

For a sustainable plan, keep **one primary resource per domain** and use every other source only when it adds a different learning mode: reference (Handbooks/MLSysbook), implementation challenge (Build Distributed Systems/AI-infra/Hands-On RL), or interview calibration (PracHub). The main risk in this catalog is overlap, not lack of material.
