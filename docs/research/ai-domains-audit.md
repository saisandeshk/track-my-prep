# AI-domain resource audit

Audit date: 2026-07-26. “Open” means the underlying instructional material was reachable without an account when checked; it does **not** mean that coursework, recordings, a certificate, or GPU compute is free. “Catalog-only / unverified” means the saved URL did not expose enough primary material to verify the claimed syllabus. Effort is reported only where the source states it; otherwise it is deliberately left as “not stated.”

## Bottom line

This collection is unusually strong in deep-learning fundamentals, transformer/LLM internals, post-training, and large-scale systems. It has too many partially overlapping advanced LLM/ML-systems routes and too little structured, practical coverage of classical ML/data-science workflow, evaluation/monitoring for deployed non-LLM models, and multimodal generative AI. Use one primary resource per stage, not every resource in that stage.

Recommended backbone: **D2L -> CMU 11-785 or CS231n -> CS336 -> RLHF Book -> CMU LLM Applications -> one systems route (MLSys Book or Scaling Book) -> one infrastructure project.** D2L alone has open math, code, and chapters from linear models through vision, transformers, RL, GANs and recommenders ([contents](https://d2l.ai/)); CS336 then supplies the end-to-end language-model build ([course](https://cs336.stanford.edu/)).

## Real gaps and minimal additions

1. **Classical ML/data-science lifecycle is underspecified.** D2L teaches models, but the set lacks a single verified resource for leakage, splits, metrics, baselines, experiment tracking, monitoring, and reproducible pipelines. Add the free, maintained [Made With ML course](https://madewithml.com/) as the practical MLOps bridge; use its [MLOps lessons](https://madewithml.com/courses/mlops/).
2. **Diffusion and modern multimodal generation need an implementation-first route.** UDL gives theory and CMU LLM Apps advertises image/music breadth, but neither verified entry is a dedicated build path. Add Hugging Face’s official free [Diffusion Course](https://huggingface.co/learn/diffusion-course/en/unit0/1) (PyTorch/Transformers familiarity required) rather than another generic LLM course.
3. **Agent evaluation/safety is dispersed.** CMU Apps, RLHF Book, Harness and the Hitchhiker preprint mention it, but no existing resource provides a compact reproducible evaluation workflow. Add the official [OpenAI Evals design guide](https://platform.openai.com/docs/guides/evals) only if the target stack uses OpenAI; otherwise implement a vendor-neutral test suite alongside the MCP/harness project. This is a tooling gap, not a reason to add another agent-framework tutorial.

## Decision rules

- Prefer **open, stable, primary instructional sources** over a playlist title, search page, personal Notion, or a preprint.
- For an academic course, separate publicly available lectures/notes from enroll-only grading, current recordings, GPU credits, and support.
- Do not start GPU kernels, distributed training, or RLHF before a working DL/Transformer implementation and basic profiling competence.
- Build one artifact per path: a reproducible ML baseline; a vision or diffusion model; a small LM/post-training experiment; an evaluated tool-using agent; and one served/observed ML service. Those artifacts resolve more overlap than consuming additional surveys.
